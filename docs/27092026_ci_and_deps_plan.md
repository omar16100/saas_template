# CI repair and dependency updates plan (27 Sep 2026)

## Goal
Make `ci.yml` and `deploy.yml` pass on `main` (both failed on every push since 19 Apr 2026), then land or close the 8 open Dependabot PRs with real CI results behind them.

## Findings (why CI never passed)
- `pnpm/action-setup` failed before install: `with: { version: 9 }` conflicts with `packageManager: pnpm@9.15.0`.
- No `pnpm-lock.yaml`, but CI runs `pnpm install --frozen-lockfile`.
- `lint` was `next lint`, which Next.js 16 removed, and there was no ESLint config.
- `db:generate` ran `drizzle-kit generate` without `--config`; the config lives at `db/drizzle.config.ts`.
- The Lighthouse job held the only `pnpm build` and ran with `continue-on-error`, and its `staticDistDir` (`.open-next/assets`) holds no HTML, so it could never produce a report.
- `pnpm build` was `opennextjs-cloudflare build`, which itself runs the app's `build` script, so it recursed forever.
- Once installable, the code did not typecheck or build:
  - `cloudflare-env.d.ts` is gitignored and generated by `wrangler types`, so `DB`, `JOBS`, `UPLOADS` were missing from `CloudflareEnv`.
  - better-auth 1.4+ moved passkeys to `@better-auth/passkey` and renamed `forgetPassword` to `requestPasswordReset`.
  - Stripe API 2025-03-31.basil (stripe-node 18) moved `current_period_end` from the subscription to its items.
  - `lib/auth.ts` built Better Auth at module load, which calls `getCloudflareContext()` outside a request and fails `next build`.
  - 4 ESLint errors (conditional hook in `turnstile.tsx`, setState in effect in `consent-banner.tsx`, 2 unescaped apostrophes).
- `deploy.yml` targets Cloudflare Workers via `wrangler deploy` and needs `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`; the repo has no secrets. The github.io landing page is GitHub Pages from the `gh-pages` branch and does not depend on either workflow.

## Decisions
- `pnpm build` is now `next build`; `pnpm build:worker` runs the OpenNext build (the recommended OpenNext script layout). CI makes `build:worker` a mandatory step; Lighthouse stays optional and now runs against `next start`.
- `pnpm typecheck` and `pnpm build` run `wrangler types` first so a fresh clone (and the deploy job) typechecks and builds.
- `getAuth()` builds Better Auth per call instead of caching it, to keep module state out of the Worker (AGENTS.md 12-Factor VI).
- `db/migrations/` is not committed: the auth schema does not yet match better-auth 1.7 plugins (see follow-ups), so an initial migration would bake that in. CI still runs `drizzle-kit generate` as a schema check.
- `deploy.yml` gates on a `config` job that checks the Cloudflare secrets; without them the deploy job is skipped and the workflow passes. When enabled, the deploy job uses GitHub environment `preview` (PRs) or `production` (main), exports that environment's non-empty `NEXT_PUBLIC_*` variables before building (Next.js inlines them), sets `NEXT_PUBLIC_IS_PREVIEW`, and fails loudly if `NEXT_PUBLIC_APP_URL` is missing.
- `pnpm run deploy` now passes `--env production` to match the README (it deployed the default localhost env before).
- Lighthouse output (`.lighthouseci`, hidden dir so `include-hidden-files: true`) is uploaded as a non-blocking PR artifact.
- `NEXT_PUBLIC_IS_PREVIEW` parsing fixed in this PR (exact `"true"` only, matching middleware.ts) because deploy.yml now exports `false` for production builds, which `z.coerce.boolean()` read as true.
- deploy.yml rejects multi-line `NEXT_PUBLIC_*` values (GITHUB_ENV injection).
- README gains a Known gaps section instead of claiming Turnstile, rate limiting and the deletion consumer are wired.
- eslint 10: close #4 and ignore eslint semver-major in Dependabot.

## Follow-ups for the owner (not done here)
- `db/schema/auth.ts` lacks what the better-auth 1.7 plugins expect: the `twoFactor` table and `user.twoFactorEnabled` (twoFactor plugin) and `passkey.aaguid` (passkey plugin). Generate the expected schema with the better-auth CLI and reconcile before first deploy.
- wrangler is on 3.x; `@opennextjs/cloudflare` 1.20 declares a peer of wrangler `^4.125.0` and warns that Next.js 16.1+ needs wrangler 4.59.2+. Upgrade before deploying.
- `components/turnstile.tsx` renders the widget only if `window.turnstile` already exists when the effect runs; with the async script this can miss. Needs an `onLoad` hook. No route calls `verifyTurnstile`.
- `lib/rate-limit.ts` has no callers; the `audit_log` table is never written; no queue consumer handles `user.purge`.
- `passkey.credentialId` in the schema vs the plugin's `credentialID` field name.
- Root layout canonical `/` is inherited by pricing, blog index and auth pages.
